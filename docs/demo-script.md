# Demo Script

A five-minute walkthrough. Use it for a screen share or to sanity-check a build. Every number below is regenerated by `python engine/build.py`, so exact values shift slightly between engine changes; the story does not.

## 0. Setup (before the call)

```bash
pip install -r requirements.txt
python engine/build.py
cd web && python -m http.server 8000
```
Open `http://localhost:8000`. Confirm the header shows study `TF-201`, Phase II, and a data-cut date.

## 1. Executive Overview (60s)

- Point to the **Trial Health Score** and its status pill. Read the five drivers: recruitment and data completeness are green, query backlog and protocol deviations are the weak points.
- "This is one number the operations lead can take into governance, and it decomposes into exactly these five things."
- Scroll to the **KPI grid**: enrolled vs target, open queries with the aged count, deviations with the major count, sites at risk.
- **Recruitment vs plan** chart: the actual line is tracking below plan. That is why the recruitment driver still matters even though it is green.

## 2. Site Performance (75s)

- "This is the CTMS view. One row per site, sorted by risk."
- Click the top row (a red site). The **detail panel** opens: recruitment far below target, above-average query load, several deviations, and a recommended action.
- "Individually none of these triggers a call. The model combines them, bands the site red, and tells the CRA what to do."
- Sort by **Open Q** to show the table is interactive.

## 3. Patient Journey / EDC (45s)

- "Now the data manager's view, for one subject."
- Walk the visit table: visits Done, one form missing at Screening, a Laboratory page missing at two later visits.
- Point to **data completeness** for the subject and the **open data items** list. "Each of these becomes a query with an owner."

## 4. Data Quality (45s)

- "Five deterministic checks over the raw EDC tables."
- **Findings by rule**: missing data and out-of-range values dominate; impossible dates and cross-form inconsistencies are rarer but higher severity.
- **Findings by site**: the same sites that are red on risk are high here. That is the feedback loop.
- Scroll to the **sample findings** table: every finding names the subject, the site and the exact location.

## 5. Protocol Deviations and Adverse Events (45s)

- Deviations: "Out-of-window visits are detected straight from the schedule, then trended by site." Point to the by-site chart.
- Adverse Events: severity, system organ class, severity by arm, and the serious-event list. "Note the banner: this is a summary of recorded data for operational oversight, not a safety assessment."

## 6. SDTM Mapping (30s)

- Show the **pipeline**: EDC &rarr; data quality &rarr; SDTM &rarr; warehouse &rarr; analytics &rarr; dashboard &rarr; action.
- Show the **DM / AE / VS / SV** cards with row counts and sample rows. "SDTMIG variable names, four domains, labelled a simplified demonstration model."
- Point to the **SQL views** table at the bottom.

## 7. Risk Copilot (30s)

- Click "Which sites require intervention this week and why?" Read the summary and the per-site breakdown.
- Click "Why is the trial health score where it is?"
- "These answers are generated from the computed metrics. No LLM. It summarises rules and analytics; it does not touch medical judgement."

## 8. Close (15s)

- Back to the repo: "The product side is here too: vision, personas, roadmap, user stories with acceptance criteria, a scored backlog and the case study."

## Build sanity checks

After any engine change, confirm:

- [ ] `python engine/build.py` exits cleanly and prints a trial-health score and red/amber site counts.
- [ ] `web/data/trialflow.json` timestamp updated; file is 90&ndash;200 KB.
- [ ] Overview KPIs are internally consistent (enrolled matches the sum by country; sites at risk = red + amber).
- [ ] Data Quality Score between 90 and 99; every `by_rule` count &gt; 0.
- [ ] At least 3 red sites and at least 3 amber sites.
- [ ] Patient Journey subject has both a missing form and an out-of-range lab.
- [ ] All eight tabs render with no console error.
